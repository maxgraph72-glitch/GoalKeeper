# Развёртывание Goal Keeper

Этот документ — основной регламент локального запуска, production-сборки и выпуска Goal Keeper для Windows.

> Статус на 13 августа 2026 года: фактический стек — Tauri 2, React 19, TypeScript 6, Vite 8, npm и SQLite через официальный SQL-плагин Tauri. Реализованы начальная схема данных, список активных целей и создание цели с автоматическим этапом «Основное». Остальные сценарии MVP ещё в работе.

## Зафиксированные границы

Goal Keeper — локальное desktop-приложение без аккаунта и серверной части. Production-сборка не должна отправлять пользовательские данные по сети, подключать телеметрию или зависеть от облачных сервисов.

- Поддерживаемая платформа MVP: Windows 10 и Windows 11, x64.
- Форматы выпуска: NSIS (`.exe`) и MSI (`.msi`).
- macOS, Linux, мобильные и web-клиенты не входят в MVP.
- Основное хранилище: локальная SQLite-база `goal-keeper.db`.
- Идентификатор приложения: `com.goalkeeper.app`.
- Текущая версия: `0.1.0`.

Идентификатор нельзя менять после появления пользовательских данных или первого выпуска без отдельного плана миграции: он участвует в определении системного каталога приложения.

## Фактическая структура проекта

```text
.
├── package.json                 # npm-скрипты и frontend-зависимости
├── package-lock.json            # воспроизводимое дерево npm-зависимостей
├── vite.config.ts               # Vite и локальный dev-сервер
├── src/                         # React + TypeScript
├── src-tauri/
│   ├── Cargo.toml               # Rust, Tauri и SQLite-плагин
│   ├── tauri.conf.json          # окно, CSP, bundle targets и preload БД
│   ├── capabilities/default.json
│   ├── icons/
│   └── src/
└── docs/
```

Ключевые настройки `src-tauri/tauri.conf.json`:

- `beforeDevCommand`: `npm run dev`;
- `devUrl`: `http://127.0.0.1:1420`;
- `beforeBuildCommand`: `npm run build`;
- `frontendDist`: `../dist`;
- bundle targets: `nsis` и `msi`;
- production CSP разрешает только ресурсы приложения и Tauri IPC;
- `devCsp` дополнительно разрешает только локальный Vite/HMR на `127.0.0.1`;
- SQL preload: `sqlite:goal-keeper.db`.

Наличие локального HTTP-адреса в `devUrl` не означает сетевую зависимость production-приложения: он используется только dev-сервером на машине разработчика.

## Требования к Windows-машине

Установите:

1. Git.
2. Node.js версии, соответствующей `engines.node` в `package.json` (`^20.19.0` или `>=22.12.0`), с npm.
3. Актуальный stable Rust через Rustup (`rustc` и `cargo`).
4. Microsoft C++ Build Tools с workload **Desktop development with C++**.
5. WebView2 Runtime, если он отсутствует.
6. Windows Script Host / VBSCRIPT для создания MSI. На некоторых системах его нужно включить в компонентах Windows.

Проверка окружения:

```powershell
node --version
npm --version
rustc --version
cargo --version
npm run tauri info
```

На машине, где каркас был создан, Node.js, npm, WebView2 и MSVC обнаружены. Rustup установлен в `%USERPROFILE%\.cargo\bin`, но этот каталог может отсутствовать в `PATH` уже открытого PowerShell. В таком случае закройте терминал и откройте новый. Если команда всё ещё не найдена, добавьте каталог для текущей сессии:

```powershell
$env:PATH = "$env:USERPROFILE\.cargo\bin;$env:PATH"
rustc --version
cargo --version
```

## Установка зависимостей

Из корня репозитория:

```powershell
npm ci
```

Используйте `npm ci` для обычной установки и сборки: команда строго следует `package-lock.json`. `npm install` нужен только при осознанном добавлении или обновлении зависимостей; после него проверьте и сохраните изменения обоих package-файлов.

## Локальный запуск

Полное desktop-приложение:

```powershell
npm run tauri dev
```

Только React-интерфейс в браузере:

```powershell
npm run dev
```

Vite слушает только `127.0.0.1:1420`. Браузерный режим подходит для работы над интерфейсом, но не подтверждает SQLite, Tauri capabilities и поведение установленного приложения.

## Доступные npm-скрипты

```text
npm run dev          # локальный Vite-сервер
npm run tauri dev    # Tauri-приложение в режиме разработки
npm run format       # проверка форматирования Prettier
npm run format:write # применение форматирования Prettier
npm run lint         # ESLint без допустимых предупреждений
npm run typecheck    # TypeScript project references без emit
npm test             # Vitest, однократный запуск
npm run test:watch   # Vitest в watch-режиме
npm run build        # typecheck и production-сборка frontend
npm run tauri build  # Rust-приложение и Windows-установщики
```

## Локальные данные

В `src-tauri/Cargo.toml` включён `tauri-plugin-sql` только с SQLite feature. Плагин регистрируется в `src-tauri/src/lib.rs`, а разрешения ограничены capability `default`.

Строка `sqlite:goal-keeper.db` разрешается SQL-плагином относительно системного каталога конфигурации приложения. Для текущего идентификатора ожидаемый путь на Windows:

```text
%APPDATA%\com.goalkeeper.app\goal-keeper.db
```

Фактический системный путь должен получать Tauri; его нельзя собирать вручную из имени пользователя или других переменных окружения.

Целевая структура после появления соответствующих функций:

```text
<app-data>/
  goal-keeper.db
  backups/
  logs/
```

Сейчас `backups/` и `logs/` не создаются: резервное копирование и файловое логирование ещё не реализованы. Не добавляйте пустые каталоги или пользовательскую базу в установочный пакет.

Правила хранения:

- миграции имеют последовательные версии и применяются только вперёд;
- каждая миграция выполняется транзакционно и покрывается тестом обновления;
- обновление не удаляет и не перезаписывает существующую базу;
- ошибка миграции останавливает запись до восстановления согласованного состояния;
- логи не содержат названия, описания или содержимое целей;
- база, журналы, резервные копии и отладочные данные не попадают в Git или bundle.

Начальная forward-only миграция находится в `src-tauri/migrations/0001_initial.sql`. Она создаёт таблицы целей, этапов и шагов. SQL-плагин применяет её транзакционно при открытии `sqlite:goal-keeper.db` до показа интерфейса. Создание цели и начального этапа «Основное» также выполняется одной транзакцией.

## Проверка перед сборкой

```powershell
git status --short
npm run format
npm run lint
npm run typecheck
npm test
npm run build
```

После установки Rust дополнительно выполните:

```powershell
npm run tauri info
npm run tauri build
```

Перед релизом вручную проверьте:

1. Создание цели, этапа и шага.
2. Сохранение данных после перезапуска.
3. Пересчёт прогресса при завершении и повторном открытии шага.
4. Просроченные шаги и шаги на сегодня с учётом локального часового пояса.
5. Архивирование и восстановление цели.
6. Подтверждение или понятную отмену необратимого удаления.
7. Запуск без интернет-соединения.
8. Клавиатурную навигацию и видимый фокус.

До реализации этих сценариев они считаются неподтверждёнными, даже если техническая сборка проходит.

## Production-сборка

Frontend без desktop-оболочки:

```powershell
npm run build
```

Результат: `dist/`.

Desktop-приложение и оба Windows-установщика:

```powershell
npm run tauri build
```

Если на машине не включён необходимый для WiX/VBSCRIPT компонент Windows, MSI-сборка завершится ошибкой на `light.exe`. Это не мешает собрать поддерживаемый NSIS-установщик отдельно:

```powershell
npm run tauri build -- --bundles nsis
```

Перед выпуском MSI включите VBSCRIPT в **Параметры → Приложения → Дополнительные компоненты → Дополнительные компоненты Windows**, затем повторите полную сборку.

Ожидаемые результаты:

```text
src-tauri/target/release/
src-tauri/target/release/bundle/nsis/
src-tauri/target/release/bundle/msi/
```

`dist/` и `src-tauri/target/` являются генерируемыми каталогами и не коммитятся.

## Smoke test установщика

Каждый release candidate проверьте на чистой или тестовой Windows x64, не только на машине разработчика:

1. Установить NSIS или MSI от имени обычного пользователя.
2. Запустить Goal Keeper из меню «Пуск».
3. Создать тестовую цель с этапом и несколькими шагами.
4. Закрыть и снова открыть приложение; данные должны сохраниться.
5. Установить следующую тестовую версию поверх текущей.
6. Проверить сохранность данных и успешность миграций.
7. Проверить запуск без сети.
8. Удалить приложение и зафиксировать фактическое поведение пользовательских данных.

Политика данных при деинсталляции ещё не подтверждена. Безопасное значение по умолчанию — не удалять пользовательскую базу автоматически; менять это можно только после отдельного согласования.

## Версии и выпуск

Используйте Semantic Versioning. Перед выпуском одна версия должна быть указана в трёх местах:

- `package.json`;
- `src-tauri/Cargo.toml`;
- `src-tauri/tauri.conf.json`.

Публичный выпуск дополнительно требует:

- сертификата подписи кода, хранящегося вне репозитория;
- подписи и проверки каждого установщика;
- публикации SHA-256 рядом с каждым артефактом;
- краткого описания пользовательских изменений;
- проверки обновления на копии базы предыдущей версии.

Секреты подписи нельзя помещать в `.env`, исходный код, npm-скрипты или историю Git. Канал публикации, сертификат и автоматическое обновление пока не настроены. Добавлять updater или сетевую доставку обновлений без отдельного решения нельзя.

## Чек-лист релиза

- [ ] Версия совпадает во всех трёх конфигурациях.
- [ ] Рабочее дерево содержит только ожидаемые изменения.
- [ ] Format, lint, typecheck, тесты и frontend build проходят.
- [ ] Rust/Tauri build проходит.
- [ ] NSIS и MSI созданы без ошибок.
- [ ] Миграции проверены на копии базы предыдущей версии.
- [ ] Smoke test выполнен на тестовой Windows x64.
- [ ] Данные сохраняются после обновления поверх предыдущей версии.
- [ ] В bundle нет базы, логов, секретов и отладочных данных.
- [ ] Установщики подписаны для публичного выпуска.
- [ ] SHA-256 опубликованы рядом с установщиками.

## Восстановление после неудачного выпуска

Откат исполняемого файла не гарантирует совместимость со схемой базы после миграции. Поэтому:

1. не выпускайте миграцию без теста обновления;
2. перед рискованной миграцией создавайте восстанавливаемую копию базы;
3. исправляйте ошибочную схему новой forward-only миграцией;
4. не заменяйте пользовательскую базу пустым файлом;
5. не предлагайте удаление данных приложения как обычный способ исправления ошибки;
6. остановите распространение версии, если она повреждает или скрывает данные.
